# Codebase Conventions

**Analysis Date:** 2026-05-02

## Naming Patterns

**Files:**
- Every module has a `module_name.h` + `module_name.cpp` pair in its own directory: `source/encode/encode.h`, `source/transport/transport.cpp`, `source/stats/stats.h`, `source/ndi_input/ndi_input.cpp`
- The shared types module is `source/lib/lib.h` (generic name for cross-cutting types)
- Entry point is flat: `source/main.cpp` (not in a directory)
- Non-module utility library: `source/url/url.h` + `source/url/url.cc` (uses `.cc` extension, not `.cpp`)
- FLTK form file: `source/ui/ui.fld` (FLUID designer output)
- FLTK callback glue: `source/ui/ui_func.cxx` (generated by FLUID, not edited directly)
- Directory-level CMakeLists.txt per module: `source/encode/CMakeLists.txt`, `source/transport/CMakeLists.txt`, etc.

**Functions:**
- `snake_case` with descriptive verb-noun naming: `pipeline_build_source()`, `run_encode_thread()`, `handle_gst_message_error()`, `setup_rist_sender()`, `refresh_devices()`
- Builder-style pipeline methods prefixed with `pipeline_build_`: `pipeline_build_amd_h264_encoder()`, `pipeline_build_software_av1_encoder()`, `pipeline_build_video_payloader()` (14+ methods, `~100%` of pipeline building)
- Callback methods suffixed with `_cb`: `transport_log_append_cb()`, `encode_log_append_cb()`, `input_listen_port_cb()`
- Handler methods prefixed with `handle_`: `handle_gst_message_error()`, `handle_gst_message_eos()`, `handle_gstreamer_message()`
- GStreamer message handlers follow pattern: `handle_gst_message_<event_type>()`

**Variables:**
- `snake_case` for local and member variables: `pipeline_str`, `video_encoder`, `datasrc_pipeline`, `bus`
- Short abbreviations for GStreamer pointers: `msg`, `err`, `debug_info`
- Config structs use descriptive names: `input_c`, `encode_c`, `output_c` (abbreviated in constructor parameters)
- Boolean flags: `is_running`, `run_monitor`, `encoder_running`
- Callback function pointers use descriptive names: `log_callback`, `statistics_callback`, `log_func`

**Types:**
- `enum class` with `snake_case` values for all enumerations: `enum class input_mode`, `enum class codec`, `enum class encoder` (defined in `source/lib/lib.h`)
- `struct` with `snake_case` name for configuration/data holders: `input_config`, `encode_config`, `output_config`, `buffer_data`, `cumulative_stats` (all in `source/lib/lib.h`)
- Classes with `lowercase` name: `encode`, `transport`, `user_interface`, `ndi_input`, `stats` (except external `homer6::url` in namespace `homer6`)
- Global singleton: `library` (the app context, defined in `source/lib/lib.h`)

## Code Style

**Formatting:**
- Tool: `clang-format` with `.clang-format` configuration
- Key settings from `.clang-format`:
  - Indent width: 2 spaces, no tabs
  - Column limit: 80 characters
  - Brace wrapping: Custom — braces after functions, classes, namespaces go on new line; braces after control statements stay on same line (multi-line only)
  - Pointer alignment: Left (`PointerAlignment: Left`)
  - Break binary operators: `NonAssignment` (break before operators like `+`, `|`, `&`)
  - Include sorting: Regrouped into 4 categories — `<x>` (priority -1), `<*.hpp>` (1), `<...>` (2), everything else (3)
  - Spaces before trailing comments: 2
  - Namespace indentation: None (namespaces don't add indentation)
  - Always break before multiline strings: `true`
- Run `cmake --build build -t format-fix` to auto-format, `cmake --build build -t format-check` to verify

**Linting:**
- Tool: `clang-tidy` with `.clang-tidy` configuration
- All checks enabled by default (`Checks: "*"`), with specific exclusions: `-google-readability-todo`, `-altera-*`, `-fuchsia-*`, `-llvm-header-guard`, `-llvm-include-order`, `-llvmlibc-*`, `-modernize-use-nodiscard`, `-misc-non-private-member-variables-in-classes`
- Identifier naming: ALL `lower_case` for functions, classes, types, members, variables, enums (see `.clang-tidy` lines 49-154)
- Template parameters: `CamelCase` (`.clang-tidy` lines 139-150)
- Pedantic narrowing conversion checks enabled: `cppcoreguidelines-narrowing-conversions.PedanticMode: true`
- Spell checking: `codespell` via `cmake --build build -t spell-check`

**Test Framework:**
- Framework: Catch2 3 (`catch2/catch_test_macros.hpp`)
- Test file: `test/source/open-broadcast-encoder_test.cpp`
- Test name style: `"Name is open-broadcast-encoder"` with `[library]` tag
- Build via CTest: `ctest --output-on-failure --no-tests=error -C Release -j 2`

## Import Organization

**Include style:**
1. C/C++ standard library headers first, using angle brackets: `#include <memory>`, `#include <string>`
2. Third-party/system headers, using angle brackets: `#include <gst/gst.h>`, `#include <FL/Fl.H>`
3. Project headers using quoted paths with directory prefix: `#include "encode/encode.h"`, `#include "transport/transport.h"`, `#include "ndi_input/ndi_input.h"`
4. Project headers in the same directory without prefix: `#include "lib.h"` (in `main.cpp`, `source/lib/lib.cpp`)
5. Project headers from third-party: `#include "RISTNet.h"` (angle brackets for system-installed, quotes for project-relative)

**Include guard:**
- Use `#pragma once` in all header files (7 files use it: `lib.h`, `encode.h`, `transport.h`, `ui.h`, `ndi_input.h`, `stats.h`, `url.h`)
- No traditional `#ifndef`/`#define` guards used

**`using` declarations:**
- Prefer qualified names (`std::string`, `std::format`, `std::thread`) in headers
- Use `using std::string;` selectively in `.cpp` files where the type dominates: `source/encode/encode.cpp:7`, `source/transport/transport.cpp:9`, `source/url/url.cc:14`

## Error Handling

**Patterns:**
- GStreamer errors handled via bus message callbacks: `handle_gst_message_error()` parses `GError*` and debug info, logs them, sets `encoder_running = false` (`source/encode/encode.cpp:428-442`)
- Pipeline parse errors checked immediately after `gst_parse_launch()`, logs error message and clears error (`source/encode/encode.cpp:358-366`)
- Buffer null checks before use: `if (buffer != nullptr)` in `pull_video_buffer()` and `pull_audio_buffer()` (`source/encode/encode.cpp:469`)
- Callback null checks before invocation: `if (log_func)` in `encode::log()` (`source/encode/encode.cpp:501-506`), `if (log_func != nullptr)` in `ndi_input::log()` (`source/ndi_input/ndi_input.cpp:119`)
- No exceptions thrown — C-style error propagation via boolean return values (`stats::got_rist_statistics()` returns `bool`)
- Resource cleanup in destructors: `gst_element_set_state(..., GST_STATE_NULL)`, `gst_object_unref()`, thread joining

**No exceptions policy:** The codebase avoids `try`/`catch` entirely. All error paths use early returns, boolean flags, or element state transitions.

## Logging

**Pattern:**
- Callback-based logging: each module holds a function pointer `log_func` (type `std::function<void(const std::string&)>` or `void (*)(const std::string& msg)`)
- Log callback injected via constructor or setter: `encode` constructor takes `log_func` parameter; `transport` uses `set_log_callback()` and `set_statistics_callback()` (`source/transport/transport.cpp:22-30`)
- Centralized log routing in `main.cpp`: `encode_log()` and `transport_log()` static functions route to UI append methods (`source/main.cpp:23-31`)
- UI displays logs via `Fl_Text_Display` with `Fl_Text_Buffer` backing: `transport_log_display`, `encode_log_display` (`source/ui/ui.cpp:443-459`)
- GStreamer library logging: RIST library callbacks (`rist_log_cb`) route through `transport_log_append()` (`source/main.cpp:42-48`)

**When to log:**
- Pipeline construction: full pipeline string logged before parsing (`source/encode/encode.cpp:356`)
- State transitions: "Playing pipeline.\n", "Stopping pipeline.\n" (`source/encode/encode.cpp:397, 407`)
- Error conditions: GStreamer parse errors, element errors, EOS (`source/encode/encode.cpp:428-462`)

## Module / Function Design

**Builder pattern for pipeline construction:**
- The `encode` class uses a cascade of `pipeline_build_*()` methods that append to `pipeline_str` string
- Top-level dispatcher: `build_pipeline()` calls sub-builders in order (`source/encode/encode.cpp:339-349`)
- Each encoder variant gets its own method: 14 encoder-specific methods for 4 encoders × 3 codecs
- Methods are named `pipeline_build_<vendor>_<codec>_encoder()`: e.g., `pipeline_build_amd_h264_encoder()` (`source/encode/encode.h:52-67`)

**Callback/event-driven architecture:**
- Components expose callback setters rather than using virtual interfaces: `set_log_callback()`, `set_statistics_callback()` in `transport` (`source/transport/transport.h:21-22`)
- UI callbacks use FLTK `FL_METHOD_CALLBACK_N` macros to bind class methods to widget events (`source/ui/ui.cpp:618-695`)
- RIST library callbacks use `std::bind_front` for member function binding: `std::bind_front(&transport::stats_cb_func, this)` (`source/transport/transport.cpp:14`)

**Global state:**
- `main.cpp` uses global instances for cross-component communication: `library app`, `transport* transporter`, `user_interface ui`, `encode* ptr_encoder`, `ndi_input ndi` (`source/main.cpp:18-21`)
- `library` struct holds all shared config, stats, and thread handles (`source/lib/lib.h:76-100`)
- Callback function pointers in `main.cpp` access globals: `ptr_encoder->set_encode_bitrate()` (`source/main.cpp:53`)

**Threading model:**
- Encoding runs in a background thread via `run_loop()` (`source/main.cpp:57-73`)
- NDI device monitoring runs in a dedicated thread (`source/ndi_input/ndi_input.cpp:16-37`)
- GStreamer bus message loop runs in the encode thread (`source/encode/encode.cpp:377-391`)
- UI updates from background threads require `Fl::lock()` / `Fl::unlock()` / `Fl::awake()` (`source/ui/ui.cpp:467-476`)
- Thread-unsafe GStreamer element access protected by single-threaded design (no shared mutable GStreamer state across threads)

**Constructor patterns:**
- Constructor initializer list uses comma-first style with brace initialization: `: encoder_running {false} , run_flag {std::move(run_flag)} , log_func {std::move(log_func)}` (`source/encode/encode.cpp:13-17`)
- `explicit` keyword on single-parameter constructors to prevent implicit conversions: `explicit ndi_input(...)`, `explicit library()`, `explicit encode(...)` (`source/lib/lib.h:81`, `source/ndi_input/ndi_input.h:15`, `source/encode/encode.h:27`)
- `noexcept` on trivial constructors: `library() noexcept` (`source/lib/lib.h:81`)

**RAII and resource management:**
- `std::unique_ptr<transport>` for transport lifetime (`source/main.cpp:19`)
- `std::shared_ptr<std::atomic<bool>>` for run flag shared between threads (`source/encode/encode.h:35`)
- `std::vector<std::thread>` for tracking worker threads (`source/encode/encode.h:34`)
- Destructors join threads and unreference GStreamer objects (`source/encode/encode.cpp:21-33`)

## Convention Adoption Rates

- **snake_case for all identifiers (functions, types, variables, members):** `~100% (stable)` — enforced by `.clang-tidy` with `lower_case` for all categories; zero violations found in any source file
- **#pragma once for header guards:** `~100% (stable)` — all 7 headers use `#pragma once`; no traditional `#ifndef` guards in the codebase
- **`enum class` with `std::uint8_t` backing:** `~100% (stable)` — all 3 enums (`input_mode`, `codec`, `encoder`) follow this pattern consistently in `source/lib/lib.h`
- **`snake_case` method naming:** `~100% (stable)` — all 40+ methods across all modules use `snake_case`; no camelCase methods found
- **`lowercase` class names:** `~100% (stable)` — all 5 project classes (`encode`, `transport`, `user_interface`, `ndi_input`, `stats`) use lowercase; matches `.clang-tidy` `ClassCase: lower_case`
- **switch/case for enum dispatch:** `~100% (stable)` — 14 switch statements across source files handle enum dispatch; zero `if-else` chains for enum values
- **Builder pattern for pipeline construction:** `~100% (stable)` — 14 `pipeline_build_*()` methods in `encode` class follow this exact pattern
- **Callback injection via function pointers:** `~100% (stable)` — logging and stats callbacks use function pointers, not virtual interfaces or std::function
- **std::format for string building:** `~100% (stable)` — all dynamic string construction uses `std::format`; zero `sprintf`/`stringstream`/`+` concatenation for format strings
- **nullptr vs NULL:** `~88% (stable)` — 7 files use `nullptr`, 2 files (url.cc, encode.cpp:498) use `NULL` for GStreamer C API compatibility
- **const correctness (const methods):** `~15% (declining)` — only 2 methods marked `const` (`encode::log()`, `ndi_input::log()`); most methods are non-const despite not mutating state
- **std::function vs function pointers:** `~40% (rising)` — `encode` uses `std::function<void(const std::string&)>`; `transport` and `ndi_input` use C-style function pointers; newer code tends toward `std::function`
- **Smart pointers:** `~25% (stable)` — `unique_ptr` in `main.cpp`, `shared_ptr` for run flags, but raw pointers still dominate (GStreamer elements, `encode* ptr_encoder`)
- **Lambda capture by reference:** `~25% (stable)` — 3 files use `[&]` lambda captures in thread construction (`source/ndi_input/ndi_input.cpp:21`, `source/encode/encode.cpp:399`)
- **Explicit keyword on constructors:** `~100% (stable)` — all 3 single-parameter constructors across modules use `explicit`
- **noexcept on trivial constructors:** `~33% (stable)` — 2 of 6 constructors use `noexcept` (`library`, `ndi_input`)

- Unit: Yes (Catch2) — examples: `test/source/open-broadcast-encoder_test.cpp`

**Where tests live:**
- Tests: `test/source/open-broadcast-encoder_test.cpp`
- Test CMakeLists.txt: `test/CMakeLists.txt`

**Test setup:**
- Catch2 via `find_package(Catch2 REQUIRED)` and `include(Catch)` (`test/CMakeLists.txt:9-10`)
- Test executable links against `open-broadcast-encoder_lib` and `Catch2::Catch2WithMain` (`test/CMakeLists.txt:15-18`)
- Tests discovered via `catch_discover_tests()` (`test/CMakeLists.txt:22`)

**Mocking boundaries (explicit):**
- **Do mock:** External hardware encoders (AMD AMF, Intel QSV, NVIDIA NVENC) — these cannot be instantiated in CI; mock via pipeline string validation
- **Do mock:** NDI device discovery (`GstDeviceMonitor`) — requires NDI runtime environment
- **Do NOT mock:** `library` struct / `input_config` / `encode_config` / `output_config` — these are plain data structs, not interfaces; pass them by reference
- **Do NOT mock:** GStreamer pipeline strings — validate pipeline construction by checking the string format directly (see `source/encode/encode.cpp:356` where pipeline is logged)
- **Do NOT mock:** `stats::got_rist_statistics()` — pure computation, no external dependencies; test with synthetic `rist_stats` data
- **Why:** The codebase uses function pointers and global state rather than abstract interfaces. Mocking would require refactoring to dependency injection or virtual interfaces. The pragmatic approach is to validate output (pipeline strings, bitrate values) rather than mock dependencies.

## External Integration Patterns (Security-Critical)

### Network Configuration
- RIST URLs constructed dynamically with parameterized addresses: `rist://{}:{}?bandwidth={}&buffer-min={}&...` (`source/transport/transport.cpp:49-60`)
- Default address is loopback: `127.0.0.1:5000` (`source/lib/lib.h:66`)
- URL parsing via `homer6::url` library: `url url{ std::format("rist://{}", output_c.address) }` (`source/transport/transport.cpp:45`)
- Multi-stream support creates port offsets: `url.getPort() + (2 * i)` for stream `i` (`source/transport/transport.cpp:54`)

### GStreamer Integration
- All GStreamer elements managed via raw pointers with manual lifecycle (`gst_object_unref()`)
- Pipeline strings built via `std::format` and parsed via `gst_parse_launch()` (`source/encode/encode.cpp:358`)
- Error handling via bus message callbacks, not return values
- SDP string hardcoded as default SDP input: `source/encode/encode.cpp:38-49`

### NDI Integration
- Device discovery via `GstDeviceMonitor` with `Video/Source` filter (`source/ndi_input/ndi_input.cpp:25`)
- Preview creates separate pipeline per NDI source (`source/ndi_input/ndi_input.cpp:64-70`)
- Device names stored as `std::vector<char*>` requiring caller to manage GStreamer string lifetime (`source/ndi_input/ndi_input.cpp:47-48`)

### No Webhooks or Authentication
- No webhook endpoints, signature verification, or auth session management
- No authentication required for RIST connections (local network broadcast)
- No secrets in source code — RIST configuration via runtime UI input only

## Golden Files

These files demonstrate the highest density of documented conventions:

- `source/encode/encode.cpp` — Builder pipeline pattern (14 encoder methods), switch/case dispatch (4 encoders × 3 codecs), `std::format` for pipeline strings, constructor initializer list with comma-first style, GStreamer error handling via bus callbacks, `nullptr` checks, `this->` for member access, RAII in destructor with thread joining, log callback injection, lambda capture for thread creation. 505 lines, most conventions present in a single file.

- `source/main.cpp` — Global state pattern (`library app`, `std::unique_ptr<transport>`, callback function pointers), `static` functions for log routing, `std::bind_front`-free callback registration (plain function pointers), `std::move` for shared_ptr parameters, switch/case for input mode dispatch, smart pointer usage (`std::make_unique`), GStreamer initialization via `gst_init()`, thread creation via `run_loop()` lambda. 130 lines, demonstrates cross-module integration.

- `source/transport/transport.cpp` — Callback setter pattern (`set_log_callback`, `set_statistics_callback`), `std::bind_front` for member function binding, `homer6::url` for URL parsing, `std::format` for RIST URL construction, RAII destructor with resource cleanup (`closeAllClientConnections`, `destroySender`), function pointer types for callbacks. 74 lines, exemplifies the callback-based component architecture.
